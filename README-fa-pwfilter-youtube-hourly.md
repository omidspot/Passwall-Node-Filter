# Passwall Node Filter (pwfilter)

ابزار فیلتر و پاک‌سازی خودکار نودهای Passwall در OpenWrt؛ با انتخاب تصادفی کانفیگ از سابسکریپشن، بررسی اتصال TCP و تست دسترسی به YouTube از طریق تک‌تک نودها.

> **هشدار مهم:** این برنامه نودهای ناموفق را واقعاً از تنظیمات Passwall حذف می‌کند. اگر اینترنت روتر، سرورهای تست YouTube یا مسیر شبکه موقتاً دچار اختلال باشند، ممکن است تعداد زیادی یا حتی تمام نودهای گروه انتخاب‌شده حذف شوند. قبل از استفاده، از تنظیمات Passwall نسخه پشتیبان بگیرید و حتماً یک گروه اختصاصی برای این ابزار بسازید.

## قابلیت‌ها

- دریافت سابسکریپشن، مرتب‌سازی تصادفی کل لینک‌های یکتا و وارد کردن آن‌ها به‌صورت دسته‌ای.
- تکمیل تدریجی فهرست تا رسیدن به تعداد نود سالم تعیین‌شده؛ یا پایان سابسکریپشن؛ یا توقف دستی.
- سقف تعداد نودهای سابسکریپشنی گروه هدف از مقدار تنظیم‌شده بیشتر نمی‌شود؛ دسته بعدی فقط به اندازه ظرفیت خالی وارد می‌شود.
- حذف لینک‌های تکراری در مرحله انتخاب.
- بررسی نودهای قدیمی و جدید گروه انتخاب‌شده در هر بار اجرا.
- بررسی TCP و سپس تست YouTube از طریق خود نود.
- حذف نود در صورت شکست تست TCP یا شکست شرط YouTube.
- اجرای دستی از پنل LuCI.
- اجرای خودکار با فاصله قابل تنظیم از ۱ تا ۲۴ ساعت.
- نمایش لاگ زنده در تب جداگانه داخل همان صفحه.
- حفظ تنظیمات موجود هنگام نصب مجدد؛ نصب‌کننده فایل تنظیمات موجود را بازنویسی نمی‌کند و فقط گزینه‌های جدیدِ غایب را اضافه می‌کند.

## سازگاری و پیش‌نیازها

این نسخه برای محیط زیر نوشته شده است:

- OpenWrt 23.05
- `luci-app-passwall`
- ساختار اسکریپت Passwall در مسیر `/usr/share/passwall/`
- وجود دستور `curl`
- وجود ابزار TCP check: در صورت نصب بودن `tcping` از آن استفاده می‌شود؛ در غیر این صورت اسکریپت تلاش می‌کند از `nc` استفاده کند.
- وجود موتور و اجزای موردنیاز Passwall برای اجرای نود به شکل SOCKS موقت (برای مثال Xray یا sing-box متناسب با تنظیمات Passwall)

نصب‌کننده وجود Passwall، فایل `subscribe.lua` و `curl` را بررسی می‌کند. با این حال، این بررسی جای آزمایش روی دستگاه واقعی را نمی‌گیرد. این پروژه روی همه مدل‌های روتر و همه نسخه‌های Passwall آزمایش‌شده فرض نمی‌شود.

## نصب

### ۱. دریافت فایل

فایل نصب‌کننده این نسخه را از بخش Releases یا فایل‌های همین مخزن دریافت کنید:

`install-pwfilter-youtube-hourly.sh`

### ۲. انتقال فایل به روتر

فایل را با SCP، WinSCP یا روش دلخواه به روتر منتقل کنید. برای نمونه، اگر فایل در پوشه `/tmp` قرار گرفته باشد:

```sh
cd /tmp
```

### ۳. اجرای نصب‌کننده

```sh
sh /tmp/install-pwfilter-youtube-hourly.sh
```

نصب‌کننده اجزای زیر را ایجاد یا به‌روزرسانی می‌کند:

- `/usr/bin/pwfilter` — اسکریپت اصلی
- `/etc/config/pwfilter` — تنظیمات ابزار
- `/etc/init.d/pwfilter` — راه‌اندازی و همگام‌سازی زمان‌بندی
- `/www/luci-static/resources/view/pwfilter/main.js` — صفحه LuCI
- فایل منو و دسترسی RPC مربوط به LuCI

در پایان نصب، صفحه LuCI را از مسیر زیر باز کنید:

**LuCI → Services → Passwall Node Filter**

اگر منو دیده نشد، یک بار از LuCI خارج و دوباره وارد شوید یا صفحه را Refresh کنید.

## تنظیمات اولیه

در تب **Settings** این موارد را تنظیم کنید:

### Subscription URL

آدرس سابسکریپشن را وارد کنید. ابزار ابتدا سابسکریپشن را دریافت می‌کند، لینک‌های قابل پشتیبانی را استخراج می‌کند و بعد از انتخاب تصادفی، فقط لینک‌های انتخاب‌شده را به Passwall می‌دهد.

**قالب‌های پشتیبانی‌شده در این نسخه:**

- فهرست لینک‌های URI، هر لینک در یک خط؛ مانند `vless://`، `vmess://`، `trojan://` و پروتکل‌های URI مشابه.
- همین فهرست در قالب Base64.

**قالب‌های پشتیبانی‌نشده:**

- Clash YAML
- SSD

اگر پاسخ سابسکریپشن در قالب قابل پشتیبانی نباشد، اسکریپت آن را رد می‌کند و از ارسال کل سابسکریپشن به Passwall خودداری می‌کند. برای این قالب‌ها باید ابتدا خروجی را به فهرست URI خط‌به‌خط تبدیل کنید.

### Maximum healthy nodes in group

این گزینه سقف تعداد نودهای سالم در گروه هدف است؛ بازه قابل تنظیم در رابط کاربری ۱ تا ۲۰۰ است. این مقدار دیگر صرفاً تعداد لینک‌هایی نیست که در یک مرحله وارد می‌شوند.

مثلاً اگر مقدار `10` باشد:

1. ابتدا تمام نودهای قدیمی گروه با TCP و سپس YouTube بررسی می‌شوند.
2. نودهای ناموفق حذف می‌شوند.
3. اگر ۶ نود سالم باقی مانده باشد، فقط ۴ کانفیگ بعدی از صف تصادفی سابسکریپشن وارد می‌شود.
4. پس از تست دوباره، اگر هنوز کمتر از ۱۰ نود سالم وجود داشته باشد، فقط به اندازه ظرفیت خالی دسته بعدی وارد می‌شود.
5. این چرخه تا رسیدن به ۱۰ نود سالم، تمام شدن لینک‌های سابسکریپشن یا فشردن دکمه Stop ادامه دارد.

بنابراین گروه هدف در طول فرآیند حداکثر ۱۰ نود سابسکریپشنی خواهد داشت و ابزار برای پر کردن ظرفیت، دسته‌های بعدی را امتحان می‌کند. اگر از قبل تعداد نودهای گروه بیشتر از سقف تنظیم‌شده باشد، پس از تست، نودهای اضافه حذف می‌شوند تا سقف رعایت شود. ترتیب نودهایی که در حالت اضافه باقی می‌مانند بر اساس ترتیب شناسه‌های Passwall است.

### Node group name

نام گروهی که Passwall نودهای سابسکریپشن را با آن ثبت می‌کند. مقدار پیش‌فرض `pwfilter` است.

**توصیه جدی:** یک گروه اختصاصی فقط برای این ابزار در نظر بگیرید. ابزار برای شناسایی نودهای قابل بررسی، نودهای دارای `add_mode=2` را در گروه مشخص‌شده پیدا می‌کند. بنابراین سایر نودهای سابسکریپشنی که در همان گروه باشند نیز بررسی می‌شوند و در صورت شکست تست حذف خواهند شد. نودهای دستی که `add_mode=2` ندارند، با این روش شناسایی نمی‌شوند.

### YouTube test URLs

فهرست URLهایی که دسترسی به آن‌ها از طریق هر نود بررسی می‌شود. مقدارهای پیش‌فرض:

```text
https://www.youtube.com/generate_204
https://www.youtube.com/robots.txt
```

می‌توانید URLهای دیگری اضافه یا جایگزین کنید. بهتر است URLها پاسخ HTTP قابل بررسی و پایدار داشته باشند.

### YouTube requirement

شرط موفقیت تست YouTube:

- `at least one URL returns HTTP 2xx` یا حالت `any`: کافی است حداقل یکی از URLها پاسخ HTTP در بازه 2xx بدهد.
- `all URLs return HTTP 2xx` یا حالت `all`: تمام URLهای تعریف‌شده باید پاسخ HTTP در بازه 2xx بدهند.

اگر نود شرط انتخاب‌شده را برآورده نکند، حذف می‌شود.

### TCP ping timeout / attempts / parallel jobs

- **TCP ping timeout:** مهلت هر تلاش برای اتصال TCP، بر حسب ثانیه.
- **TCP ping attempts:** تعداد تلاش برای هر نود.
- **TCP ping parallel jobs:** تعداد بررسی‌های TCP که هم‌زمان اجرا می‌شوند.

در تست TCP، اتصال به آدرس و پورت سرور نود بررسی می‌شود. این مرحله قبل از تست YouTube است.

### YouTube test timeout / parallel jobs

- **YouTube test timeout:** حداکثر زمان هر درخواست تست YouTube، بر حسب ثانیه.
- **YouTube test parallel jobs:** تعداد تست‌های YouTube که هم‌زمان اجرا می‌شوند.

برای روترهای ضعیف، مقدار هم‌زمانی کمتر می‌تواند فشار پردازشی و حافظه را کاهش دهد؛ در مقابل، زمان پایان اجرای کل کار ممکن است بیشتر شود.

### Stop Passwall during the run

اگر فعال باشد، Passwall قبل از تست TCP متوقف می‌شود تا بررسی TCP از مسیر مستقیم اینترنت انجام شود. این گزینه به‌صورت پیش‌فرض فعال است.

### Start Passwall again afterwards

اگر گزینه قبلی باعث توقف Passwall شده باشد و این گزینه نیز فعال باشد، اسکریپت در پایان اجرای کار Passwall را دوباره راه‌اندازی می‌کند.

این دو گزینه مربوط به رفتار Passwall در زمان اجرای فیلتر هستند؛ زمان‌بندی خودکار، زمان‌بندی روشن/خاموش شدن Passwall نیست.

## اجرای خودکار هر چند ساعت

برای فعال کردن زمان‌بندی:

1. در تب **Settings** گزینه **Enable automatic pwfilter run** را فعال کنید.
2. در گزینه **Run automatically every (hours)** فاصله را از ۱ تا ۲۴ ساعت انتخاب کنید.
3. روی **Save & Apply** بزنید.

مثلاً مقدار `1` اجرای زمان‌بندی‌شده را هر ساعت فعال می‌کند. مقدار `3` اجرای زمان‌بندی‌شده را هر سه ساعت، در ساعت‌های متناظر با زمان‌بندی cron، اجرا می‌کند.

**نکته درباره زمان اجرا:** زمان‌بندی با cron و در دقیقه صفر ساعت‌های متناظر انجام می‌شود؛ این زمان‌بندی الزاماً یک ساعت کامل پس از لحظه فعال‌سازی یا پایان اجرای قبلی نیست. اگر یک اجرا هنوز در حال انجام باشد، اجرای هم‌زمان جدید به‌دلیل قفل اجرا نمی‌شود.

برای غیرفعال کردن زمان‌بندی، تیک **Enable automatic pwfilter run** را بردارید و **Save & Apply** کنید. این کار فقط زمان‌بندی pwfilter را حذف می‌کند و برنامه‌های زمان‌بندی مستقل Passwall را تغییر نمی‌دهد.

## اجرای دستی و توقف

در همان صفحه:

- **Run now:** اجرای فیلتر را در پس‌زمینه شروع می‌کند.
- **Stop:** تلاش می‌کند اجرای جاری را متوقف کند.
- **Live log:** لاگ را به‌صورت زنده نمایش می‌دهد.

پیش از اجرای دستی، تنظیمات را با **Save & Apply** ذخیره کنید.

## ترتیب کار در هر اجرا

1. سابسکریپشن دریافت و قالب آن بررسی می‌شود.
2. تمام لینک‌های URI یکتا استخراج و با ترتیب تصادفی در صف قرار می‌گیرند.
3. نودهای قدیمی گروه با TCP و سپس YouTube آزمایش می‌شوند و ناموفق‌ها حذف می‌شوند.
4. اگر تعداد نودهای سالم کمتر از سقف باشد، فقط به تعداد ظرفیت خالی از ابتدای صف تصادفی وارد Passwall می‌شود.
5. تمام نودهای گروه، شامل قدیمی و تازه، دوباره با TCP و سپس YouTube آزمایش می‌شوند.
6. نودهای ناموفق حذف می‌شوند و تعداد سالم باقی‌مانده محاسبه می‌شود.
7. اگر تعداد سالم به سقف نرسیده باشد، دسته بعدی فقط به اندازه ظرفیت خالی وارد می‌شود و چرخه تکرار می‌شود.
8. فرآیند با رسیدن به سقف سالم، تمام شدن صف سابسکریپشن یا فشردن Stop پایان می‌یابد.
9. در پایان، اگر Passwall طبق تنظیمات متوقف شده باشد، در صورت فعال بودن گزینه مربوطه دوباره راه‌اندازی می‌شود.

### سیاست حذف نودها

در این نسخه، تست TCP و YouTube هر دو شرط لازم هستند:

- شکست TCP: حذف نود، چه قدیمی باشد چه جدید.
- موفقیت TCP و شکست شرط YouTube: حذف نود، چه قدیمی باشد چه جدید.
- موفقیت هر دو مرحله: نگه‌داشتن نود.

**محافظ حذف گروهی در این نسخه وجود ندارد.** اگر تست TCP برای همه نودها شکست بخورد، همه آن‌ها از گروه هدف حذف می‌شوند. اگر TCP موفق باشد اما تست YouTube برای همه نودهای باقی‌مانده شکست بخورد، همه آن نودها حذف می‌شوند. سپس ابزار برای پر کردن ظرفیت خالی، سراغ دسته بعدی سابسکریپشن می‌رود. اگر تمام لینک‌ها تمام شوند و تعداد سالم به سقف نرسد، با همان تعداد سالم موجود متوقف می‌شود. اختلال موقت اینترنت یا URL تست می‌تواند باعث حذف گسترده شود.

## لاگ و عیب‌یابی

لاگ اجرای فعلی در این مسیر نوشته می‌شود:

```sh
cat /tmp/pwfilter.log
```

برای مشاهده زنده از SSH:

```sh
tail -f /tmp/pwfilter.log
```

برای بررسی وضعیت زمان‌بندی cron:

```sh
cat /etc/crontabs/root
```

برای اجرای دستی از SSH:

```sh
/usr/bin/pwfilter run
```

برای شروع در پس‌زمینه:

```sh
/usr/bin/pwfilter bg
```

برای درخواست توقف اجرای جاری (فرآیند اصلی با دریافت سیگنال متوقف می‌شود و پاک‌سازی انجام می‌گیرد):

```sh
/usr/bin/pwfilter stop
```

برای مشاهده تنظیمات:

```sh
uci show pwfilter
```

اگر ابزار اجرا نشد، ابتدا این موارد را بررسی کنید:

- آدرس سابسکریپشن معتبر و قابل دریافت باشد.
- سابسکریپشن در قالب URI خط‌به‌خط یا Base64 آن باشد.
- Passwall و فایل `/usr/share/passwall/subscribe.lua` وجود داشته باشند.
- `curl` نصب باشد.
- ابزار TCP check (`tcping` یا `nc`) در سیستم موجود و قابل اجرا باشد.
- نام گروه دقیقاً با گروه موردنظر در Passwall یکسان باشد.
- فضای آزاد و حافظه روتر برای اجرای هم‌زمان تست‌ها کافی باشد.

## پشتیبان‌گیری و بازگشت

پیش از نصب یا اجرای اول، از تنظیمات Passwall و فایل‌های پیکربندی نسخه پشتیبان بگیرید. برای تهیه یک نسخه از تنظیمات UCI مربوط به Passwall:

```sh
uci export passwall > /root/passwall-backup.txt
```

برای پشتیبان گرفتن از تنظیمات خود pwfilter:

```sh
uci export pwfilter > /root/pwfilter-backup.txt
```

نصب‌کننده در نصب مجدد، اگر `/etc/config/pwfilter` از قبل وجود داشته باشد، آن را از نو نمی‌سازد؛ گزینه‌های جدیدی را که وجود ندارند اضافه می‌کند. با این حال، همیشه پیش از تغییرات نسخه پشتیبان تهیه کنید.

## نکات فنی و محدودیت‌ها

- شناسایی نودها بر اساس نام گروه و `add_mode=2` انجام می‌شود؛ ابزار شناسه قابل اتکایی برای تشخیص اینکه هر نود را دقیقاً کدام نمونه از pwfilter ساخته است در نظر نمی‌گیرد.
- بنابراین گروه اختصاصی ضروری است تا نودهای سابسکریپشنی دیگر ناخواسته حذف نشوند.
- انتخاب تصادفی فقط برای لینک‌های URI پشتیبانی‌شده انجام می‌شود. قالب‌های ناشناخته به‌جای وارد کردن کامل سابسکریپشن رد می‌شوند.
- تست YouTube با اجرای SOCKS موقت از طریق اسکریپت Passwall و درخواست `curl` انجام می‌شود.
- موفقیت YouTube بر اساس دریافت کد HTTP در بازه 2xx سنجیده می‌شود.
- این ابزار تضمین نمی‌کند هر نودی که در یک لحظه ناموفق است همیشه خراب باشد؛ خطای شبکه، DNS، محدودیت سرور مقصد یا بار زیاد روتر هم می‌تواند روی نتیجه اثر بگذارد.
- این پروژه پیش از استفاده عملی باید روی نسخه OpenWrt و Passwall دستگاه مقصد آزمایش شود.
